# 记忆碎片：核心代码与答辩准备

这份讲解以当前项目实际代码为准。代码块是讲解摘录，不是需要重新复制替换的完整脚本。没有修改游戏功能。

## 1. 开场怎么介绍（约一分钟）

这个原型将静态分层插画做成三维场景中的记忆展示。玩家第一次点击雾团，体积雾淡出，相机推进，插画通过反向溶解逐渐显现；显现边缘同时产生光点。画面完整后，前景猫自动下落，并有轻微回弹。玩家第二次点击图片，插画溶解，光点沿着消失的边缘飘出，再逐渐缩小和淡去。

主要技术是程序化三维噪声、体积雾、基于噪声阈值的图片溶解、与溶解同步的 GPU 粒子，以及基于状态和信号的动画组织。插画是平面素材，但它们放在不同深度；开场雾则是实际的体积效果。

## 3. 状态机：为什么连续点击不会乱

```gdscript
enum MemoryState { FOG, REVEALING, EXPLORING, DISSOLVING, FINISHED }

func interact() -> void:
    match state:
        MemoryState.FOG:
            reveal_memory()
        MemoryState.EXPLORING:
            dissolve_memory()
```

流程：雾等待 → 正在显现 → 展示图片 → 正在消散 → 结束。

- 输入只在 FOG 和 EXPLORING 两个状态下触发动作。
- 动画过渡中再次点击，不启动第二段相互冲突的动画。
- `interact()` 统一接受“确认”动作，鼠标输入与动画逻辑分开。
- EXPLORING 是代码里保留的状态名；目前表示图片展示阶段，不代表仍有 hover 探索。

答辩表达：用有限状态机约束合法操作，避免多个 Tween 同时修改同一个参数。

## 4. 溶解 Shader：最重要的一段

```glsl
vec4 image = texture(picture, UV);
float noise_value = texture(noise_texture, UV * noise_scale).r;

vec2 distance_to_edge = min(UV, vec2(1.0) - UV);
float inward = min(distance_to_edge.x, distance_to_edge.y) * 2.0;
float field = inward * 0.55 + noise_value * 0.45;

float threshold = mix(-0.2, 1.2, progress);
float remaining = field - threshold;
float visible_mask = smoothstep(0.0, 0.025, remaining);
ALPHA = image.a * visible_mask;
```

### 每个变量怎么解释

- **UV**：图片上的二维坐标，通常范围为 0～1，不是屏幕像素坐标。
- **noise_value**：噪声纹理在当前位置的数值，决定局部消失顺序。
- **inward**：到矩形画布最近边缘的距离，边缘小、中心大。
- **field**：给图片每个位置分配一个“消散顺序值”。55% 来自边缘距离，45% 来自噪声。
- **progress**：整个效果的进度，0 是完整图片，1 是完全消失。
- **threshold**：随进度移动的阈值。
- **smoothstep**：在小范围内平滑过渡，避免透明度呈现生硬的二值跳变。
- **image.a**：PNG 原本的透明度，确保图片空白处仍然透明。

例子：某个位置的 field 为 0.5。当 threshold 低于它时，该位置可见；阈值越过它时，该位置消失。

`mix(-0.2, 1.2, progress)` 等价于 `-0.2 + 1.4 * progress`。起终点多留余量，是为了保证开始完整、结束彻底消失。实际可见变化主要发生在中间区间。

与渐隐的区别：渐隐让所有位置一起变透明；溶解让不同位置根据 field 先后消失。

注意：方向参考的是矩形画布边缘，不是猫轮廓的精确距离场。PNG alpha 只负责屏蔽透明部分。

### 发光边缘

```glsl
float edge = 1.0 - smoothstep(0.0, edge_width, remaining);
edge *= visible_mask;
ALBEDO = mix(image.rgb, edge_color.rgb, edge);
EMISSION = edge_color.rgb * edge * edge_strength;
```

剩余可见部分中，靠近阈值的一条窄带被染成亮色，并增加自发光。`edge_width` 控制这条带在数值场中的宽度，不是固定像素宽度。

Emission 不等于光照模拟，也不自动照亮旁边的物体；向周围扩散的屏幕光晕通常还需要 Glow。当前不要宣称实现了真实发光照明。

## 5. 一套 Shader 如何既显现又消散

```gdscript
tween.tween_property(
    material, "shader_parameter/progress", 0.0, reveal_duration
).set_delay(reveal_delay)
```

初始化先设 progress = 1；上面这段将它变为 0，所以是反向溶解，图片逐渐出现。消散时目标值改为 1。

Tween 是引擎提供的数值插值工具，不是播放提前做好的视频。脚本给出起点、终点、时长和缓动方式，引擎逐帧更新。

```gdscript
tween.set_parallel(true)
tween.set_trans(Tween.TRANS_SINE)
tween.set_ease(Tween.EASE_IN_OUT)
await tween.finished
```

- parallel：雾淡出和多张图片显现并行进行。
- SINE + IN_OUT：起步和结束较慢，中间较快。
- await：当前函数等待完成，不会阻塞整个引擎。

## 6. 粒子怎么知道溶解边缘在哪里（重点回答）

### A. 在图片有效区域采样

```gdscript
var uv := Vector2(randf(), randf())
var pixel := Vector2i(uv * Vector2(picture_image.get_size()))
if picture_image.get_pixelv(pixel).a < 0.2:
    continue
```

随机选图片上的位置，跳过透明区域。不是把每一个像素都转换成一颗粒子，而是有限数量的采样。

### B. 重用 Shader 的同一套计算

```gdscript
var field := inward * 0.55 + _sample_noise(noise_image, uv * noise_scale) * 0.45
```

CPU 读取的是该图层材质实际使用的噪声纹理。`_sample_noise()` 使用重复寻址与双线性插值，使结果尽量贴近 GPU 采样。

亮边中间位置大约满足：

```text
field - threshold = edge_width / 2
threshold = -0.2 + 1.4 × progress

所以：birth = (field - edge_width / 2 + 0.2) / 1.4
```

birth 就是该采样点应该产生粒子的进度。

### C. 进度经过它时释放一次

```gdscript
var reached: bool = progress <= sample.birth if revealing else progress >= sample.birth
if not reached:
    continue
emit_particle(sample.transform, sample.velocity, Color.WHITE, Color(), flags)
edge_samples.remove_at(index)
```

- 显现时 progress 从 1 降到 0，所以判断“小于等于”。
- 消散时从 0 升到 1，所以判断“大于等于”。
- 每次直接读材质当前进度，因此动画改慢、改快或换缓动，都仍能跟随。
- 发出后删掉采样点，保证每个点只产生一次粒子。

这是沿边缘的离散近似，不是逐像素精确模拟。采样数量、帧率、纹理过滤都会影响吻合程度，也没有计算被其他图层遮住的采样点是否可见。

### D. 图片坐标转成三维位置

```gdscript
var point := Vector3(
    bounds.position.x + uv.x * bounds.size.x,
    bounds.position.y + (1.0 - uv.y) * bounds.size.y,
    0.04
)
var transform := Transform3D(layer.global_basis, layer.to_global(point))
```

UV 先映射到图片平面的局部位置，再变到世界空间。`1 - uv.y` 对齐图片向下的坐标与场景向上的 Y 方向；Z 的小偏移让粒子略微位于图片前方。

每次启动效果时重新采样图层当前变换，所以猫移动后再消散，粒子出生位置仍跟随新的位置。消散开始时会停止猫的移动，避免出生位置与移动中的图层分离。

### CPU 和 GPU 分工

CPU：选择采样点、计算出生进度、判断何时释放。

GPU：模拟粒子运动、寿命颜色与尺寸变化，并绘制粒子。

不是整个系统全在 GPU，也没有自己编写完整物理引擎。

## 7. 光点为什么会缩小和淡去

```gdscript
shrink.add_point(Vector2(0.0, 1.0))
shrink.add_point(Vector2(0.25, 1.0))
shrink.add_point(Vector2(0.7, 0.25))
shrink.add_point(Vector2(1.0, 0.0))
motion.scale_curve = shrink_texture
```

曲线横轴是每颗粒子的寿命比例，纵轴是尺寸倍率。前 25% 保持大小，70% 时缩到四分之一，结束时缩为零。随机倍率 `scale_min/scale_max` 使光点不完全一样。

透明度由另一条 Color Ramp 控制，先逐渐达到最亮，再在寿命后段淡去。尺寸变化和透明度变化是两个独立通道。

光点使用径向透明贴图和加法混合。它是三维空间中的 billboard 粒子，不是实体小球。对微小光点这样做节省几何开销，也能保持柔和外观。

## 8. 开场雾为何现在是 3D

节点已经从 MeshInstance3D 改为 FogVolume，尺寸为 4.5 × 3.5 × 1.8。材质使用 `shader_type fog`。

```glsl
vec3 p = UVW;
vec3 q = p * detail_scale + vec3(t * 0.3, -t, t * 0.2);
float broad = texture(cloud_noise, q + warp * warp_strength).r;
```

- UVW 有三个坐标，表示雾体内部位置。
- cloud_noise 是 64³ 的 NoiseTexture3D，底层为 FastNoiseLite 的 Simplex Smooth。
- 随时间改变采样位置，让纹理连续流动，而不是每帧随机换一张图。
- warp 也是噪声生成的三维偏移；用它扭曲采样坐标，就是域扭曲。
- 大噪声控制主体，细噪声补充颗粒，椭球遮罩让边缘逐渐变淡。

```glsl
DENSITY = amount * density * fog_opacity;
ALBEDO = fog_color.rgb;
EMISSION = fog_color.rgb * glow_strength * mix(0.85, 1.05, broad);
```

Shader 提供三维密度、颜色和发光数据，Godot 的体积渲染系统负责沿视线累积效果。`fog_opacity` 最终乘在密度上，因此点击后实际减少的是雾密度。

这是程序化体积雾，不是求解 Navier–Stokes 方程的流体模拟。它具有空间厚度，但没有真实烟气的压力、温度、碰撞或流体守恒。

### 为什么出现过抖动

细噪声、高对比和运动容易超过体积采样的分辨能力；帧间采样变化可能表现为闪动。我们减慢细节移动、降低高频对比，并增强时间重投影平滑。这是针对采样稳定性的调整，不是已经证明所有抖动只有一个原因。平滑也可能带来拖影，细节与稳定性需要折中。

## 9. 猫的自动运动和回弹

```gdscript
memory_preview.reveal_finished.connect(open_layer)
memory_preview.exploration_ended.connect(stop_exploration)
```

记忆显现完成后发出信号，猫接到信号才播放动画。记忆控制器不需要知道猫具体怎么移动。

动作顺序：等待 → 下落 → 向上 0.02 → 回到落点。

```gdscript
target = start_position + Vector3(0.0, -slide_distance, 0.0)
# 上弹目标：target + Vector3.UP * bounce_height
# 最终目标：target
```

上弹用 QUAD/EASE_OUT，开始快、接近最高点慢；再次下落用 QUAD/EASE_IN，开始慢、随后加速。这是手工设计的缓动动画，不是真实重力碰撞或弹簧模拟。

用户提前点击消散时，会 kill 尚未完成的移动 Tween，猫留在当时位置，再从该位置生成消散光点。

## 10. 演示相机为何独立

```gdscript
memory.reveal_started.connect(_push_in)
var target := start_position - camera.basis.z * push_distance
tween.tween_property(camera, "position", target, move_duration)
```

相机看向自身的 -Z 方向，因此减去 basis.z 就是向前推进。当前是同一台相机的位置动画，不是切换两台相机，也不是修改 FOV 的镜头变焦。

MemoryDemoCamera 放在测试场景根节点下，不在 MemoryPreview 内。将记忆分支保存为独立场景时，可以不带走这个演示控制器。

## 11. 鼠标点击如何映射到 3D

雾团点击通过 Area3D 的 input_event 接收。图片点击则把屏幕指针变成相机射线，再转到每层图片的局部坐标，与局部 Z=0 平面求交：

```gdscript
var distance := -local_origin.z / local_direction.z
var hit := local_origin + local_direction * distance
```

这来自射线公式 P(t)=O+tD，令其 Z 分量为 0 即可求 t。然后检查交点是否落在图片矩形范围内。

范围检查不是逐像素 alpha 检测，因此点击图片矩形内部的透明位置也可能被接受。当前适用于本场景中面向局部 Z 方向的图片平面。

## 13. 老师可能问什么

**图形学体现在哪里？**

二维/三维纹理采样、噪声数值场、阈值遮罩、平滑插值、域扭曲、体积密度渲染、粒子模拟、透明混合和坐标变换。最能展示自己理解的是粒子与溶解阈值同步的推导。

**人机交互体现在哪里？**

点击触发状态变化，相机和视觉反馈让用户明确知道进入/退出记忆；过渡期间限制重复输入，参数化动画便于调整节奏。目前是基础点击交互，已取消 hover，尚未接手势或开展用户测试。

**为什么用平面插画，不全部做三维模型？**

平面插画符合记忆的绘画风格，并节省资产制作成本；把它们放到不同深度可获得遮挡和视差。雾有实际体积，光点在三维空间运动。整体是混合表达，不是完整三维重建。

**为什么材料要独立，Shader 却能共享？**

Shader 是算法；ShaderMaterial 保存图片、噪声和 progress 等参数。图层共享算法，但运行时使用独立材质，避免修改一个图层影响另一个。

**改动画时长会让粒子错位吗？**

系统比较的是材质实际的 progress，不是另写一个固定秒数计时器，所以时长和缓动改变时仍会跟随边缘。它仍受每帧检查和有限采样的精度限制。

**为什么粒子不是精确的一像素一颗？**

全分辨率转换成本高，且不符合稀疏碎光的视觉目标。现在在不透明区域采样，只在临界进度发射，兼顾表现和开销。

**性能开销在哪里？**

体积雾分辨率、透明粒子重叠、图片读取及采样准备都有开销。当前还没有正式 GPU 性能测量，不能承诺具体帧率。粒子图像读取可以后续缓存，避免每次转场都读取纹理；雾细节也要按设备调整。

**怎么接手势？**

识别到一次确认手势后调用 interact()，不用重写显现与消散。需要另外实现手势稳定检测和防重复触发。原来的 hover 手势入口已随 hover 功能移除，不应宣称仍已接好。

**怎么放进正式地图？**

MemoryPreview 可以保存为独立场景。地图要开启体积雾并管理相机、船控制和退出流程。当前点击检测仍引用记忆内的 Camera3D；如果换成地图相机需要调整这一处。消散全部结束的通知、回到地图和再次播放复位还需接入，不能说已经全部完成。

**现有测试说明什么？**

自动检查覆盖了状态切换、显现/消散边缘触发、镜头目标位置、猫自动移动最终落点和粒子缩小曲线。无界面测试不能证明烟雾视觉质量、GPU 性能或手势可用性。演示前必须实际按 F6 走完整流程。
